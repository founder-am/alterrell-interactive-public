## Headline finding, before the tables

**The card studio tool renders cards that do not match the live platform component it claims to share class names with.** `tools/ai-card-studio.html` reuses `.carousel__card`, `.carousel__card-head`, `.carousel__card-title`, `.carousel__card-source`, etc. — the exact class names from `alterrell-interactive.css` — explicitly so "Puppeteer selectors work" (its own header comment, line 11). But it hardcodes different values under those names:

| Element | Card studio (`tools/ai-card-studio.html`) | Live platform (`alterrell-interactive.css`) |
|---|---|---|
| `.carousel__card-title` | DM Sans, weight 500, **12px** (line 529–532, marked `/* LOCKED */`) | DM Serif Display (`--font-editorial`), **1rem = 16px** (css line 1730–1736), no weight override |
| `.carousel__card-label` (comp-tag) | DM Mono, **9px**, lane color (line 517–522, `/* LOCKED */`) | DM Mono, `var(--text-micro)` = **10px**, lane color (css line 1720–1728) |
| `.carousel__card-source` | DM Mono, 8px, flat **`#999`** regardless of lane (line 538–542, `/* LOCKED */`) | DM Mono, `var(--text-micro)` = 10px, **`var(--c-ink-label)`** — teal or gold depending on lane (css line 1755–1760) |
| `.carousel__card-head` padding | `0.75rem 0.875rem` (line 491–495, `/* LOCKED */`) | `0.875rem 1rem 0.625rem` (css line 1699–1702) |
| `.carousel__card-foot` padding | `0.5rem 0.875rem` (line 508–513, `/* LOCKED */`) | `0.5rem 1rem 0.625rem` (css line 1712–1717) |
| `.carousel__card-head` bottom border | Applied to **every** card head unconditionally (line 494) | Applied only to `.card--a .carousel__card-head` (css line 1763–1766) |

Every one of these is marked `/* LOCKED */` in the tool's source — i.e., asserted as fixed and correct — while disagreeing with the file that is actually canonical for that CSS (`alterrell-interactive.css`, SKEL-05). A card exported from this tool via `export-all-btn`'s `html2canvas` pipeline would not visually match a card built directly against the platform stylesheet, despite both claiming the same class names. This is a tool-fidelity bug, not a documentation gap — it would silently produce wrong PNGs if used for the D-77/SHARE-04 pre-rendered share-card pipeline. Also notable: Bible's own **CARD-07** cites comp-tag as "DM Mono 9px" (from AMR §8) — the card studio matches that 9px figure, but the *live* carousel component's own `--text-micro` token resolves to 10px. So there's a three-way mismatch (Bible says 9px, live CSS token says 10px, tool says 9px) on the same element, not just a two-way tool-vs-CSS conflict.

Not fixed in this pass — read-only session, flagging only.

## Step 3 — Shell definition report (as actually built)

**Shell A — Stat.** Body = `carousel__card-stat` (adjustable size 28–72px, default 36px) + `carousel__card-text` (adjustable 11–16px, default 13px), stat-to-body gap adjustable 4–32px (default 12px). Vertical-align toggle: `top` (default) or `center` (`va-center` class). *(tools/ai-card-studio.html:891–913, 546–564)* Browse-mode sub-variants: `stat-top`, `stat-center`, `dual-stat` — the last splits the card into two columns, one stat-only, one text-only, via `.browse-dual` grid. *("var BROWSE_VARIANTS = { A: ['stat-top', 'stat-center', 'dual-stat'], ...}"* — tools/ai-card-studio.html:1504)* VISUAL-REFERENCE.html's own Shell A example (Cardi B, "$70K"/"$300K" dual-stat + editorial line, line 127–147) matches the `dual-stat` variant conceptually, though it's built as a bespoke Concert Tax card, not through this tool.

**Shell B — Chart.** Body = `.s-bars` wrapping repeated `carousel__bar-row` (label + track + value), each row built from a `{label, pct, value}` object in `card.bars[]`. Adjustable: bar height 10–24px (default 14), row gap 4–16px (default 8), label column width 56–120px (default 72px). *(tools/ai-card-studio.html:916–933, 568–607)* Browse variants: `standard`, `tiered-bar` — the latter shrinks each successive row's track height (`h = max(6, 22 - i*4)`) for a decreasing-emphasis ranked look. *(tools/ai-card-studio.html:1505, 1551–1554)* **Ranked bar list maps to Shell B** — confirmed by VISUAL-REFERENCE.html's own shell table ("B — Chart | ... | A1 horizontal bar, **B2 ranked list**, B3 progress" — VISUAL-REFERENCE.html:108) and by CHART-LIBRARY-REFERENCE.html's B2 component definition (".ac-ranked", CHART-LIBRARY-REFERENCE.html:520–557), which uses the identical bar-row anatomy and shows exactly 4 rows per card with annotation lines, same as every other Shell B example in that file.

**Shell C — Quote.** Body = optional quote-mark glyph (adjustable 0–64px; 0 hides it) + `carousel__card-quote` (adjustable 12–20px, default 15px) + `carousel__card-attribution`, attribution-gap adjustable 4–24px (default 12px). *(tools/ai-card-studio.html:936–953, 609–638)* Browse variants: `teal-field` (solid-teal card background, white text — mirrors the Chart Library's "Option 1" surface), `white-field` (default lane surface), `two-column` (quote and attribution/mark side-by-side in a 1.4fr/1fr grid rather than stacked). *(tools/ai-card-studio.html:1506, 1562–1575)* **Coverage gap:** none of these three variants implement the D4a Split Card or D4b Heavy Rule Divider patterns that are the *currently approved* Shell-C connector components (CHART-LIBRARY-REFERENCE.html:956–1000) — the tool only builds quote-style cards. VISUAL-REFERENCE.html's own Shell C section (line 109, 292–304, 319) still documents the plain "D4 connector, 2 beats, divider line" pattern that was cut and replaced by D4a/D4b on 2026-06-09 (CHART-LIBRARY-REFERENCE.html:1080) — so the doc describing Shell C and the tool building Shell C have each drifted from the currently-approved component set, in two different directions.

**Shell D — Comparison.** Body = `carousel__compare-grid`, two `carousel__compare-cell`s (value + description each). Adjustable: value size 16–32px (default 24), cell padding 8–20px (default 12), description size 9–14px (default 11). *(tools/ai-card-studio.html:956–973, 640–669)* Browse variants: `side-by-side` (the only documented layout — two columns, `1fr 1fr`) and `stacked-contrast` (two **rows** instead of columns, one cell visually accented in solid teal). *(tools/ai-card-studio.html:1507, 1576–1593)* **Coverage gap, mirrored from Shell C:** `stacked-contrast` has no counterpart anywhere in VISUAL-REFERENCE.html, which documents only the side-by-side/2-column layout for Shell D (line 110, 328–357).

## Step 4 — CARD-05 vs CARD-06 reconciliation

**The question:** a ranked bar list of 10 cities by partner mentions — does it cap at 5 rows (CARD-05) or 4 items (CARD-06)?

**Evidence:**
- A ranked bar list is, by name and construction, the **B2 component**, and B2 is explicitly filed under **Shell B** in both reference files (VISUAL-REFERENCE.html:108, CHART-LIBRARY-REFERENCE.html:520–557). It is not a generic "list" outside the shell system — it *is* a Shell B chart.
- Every live Shell B example in both files, without exception, shows **4 rows maximum per card**, with a "1 of 2" / "2 of 2" split-plus-shared-title pattern once a data set exceeds 4 (CHART-LIBRARY-REFERENCE.html:196–262, the Concert Tax gross-revenue example splits 8 artists into two 4-row cards).
- CARD-05's 5-row figure traces to **D-91**, and the Bible's own Appendix A entry for D-91 says its *dimension* portion (380×660) was "reversed by D-99," while its row-cap portion was "retained" as CARD-05 — via Appendix C's conflict **C-a**, which explains D-91 was written with a blanket, imprecise scope and that its 380×660 card format is presently the **deferred, inactive** exception (CARD-04, D-108 — "no live enforcement surface" until Crowning Achievements builds). CARD-05's 5-row number was carried over from that same D-91 ruling without being re-scoped to the *default*, currently-active 300×280 Shell B card.

**Recommended resolution:** CARD-06 governs. A ranked bar list is a named Shell B component; Shell B's cap is 4 items with a mandatory split-plus-"N of N" beyond that; every constructed example of this exact component in the reference files honors 4, never 5. CARD-05's 5-row figure is inherited from a card geometry (380×660) that isn't presently live for any shipped piece, and applying it to a standard 300×280 Shell B card conflates two different card formats that were never meant to share one cap.

For the concrete case in the prompt — 10 cities — this means a compliant build needs **at least 3 cards of ≤4 rows each** (or an uneven split, e.g. 4/4/2), each carrying an explicit "N of N" indicator, not 2 cards of 5.

**One thing the files don't fully settle:** CARD-05 and CARD-06 are not formally scoped against each other anywhere in the Bible — nothing in the text says "CARD-05 applies only to 380×660 cards" or "CARD-06 supersedes CARD-05 for Shell B specifically." My reading above is inference from the shell-identity evidence and the Appendix A/C history, not a stated rule. If AMA wants this airtight, CARD-05's text could be amended to read "...caps at 5 rows (380×660 card-native carousels only — see CARD-04)" so it stops appearing to compete with CARD-06 for standard cards. Not made in this pass — read-only session.

*(Observational aside, not an action item: `gay-uncles/index.html`'s existing "M-1" ranked-bar card — "Where bigger Black gay men found their person" — carries all 10 cities in one unsplit card with tier labels only, no "N of N" indicator. Under either CARD-05 or CARD-06 this doesn't pass; noted for whoever next touches that card, not fixed here.)*
